# План улучшений PII-маскировщика

## Приоритет 1 (Critical - влияет на основные ошибки)

### 1. Нормализация с offset mapping
- [ ] `app/pii/normalization.py` - новый модуль
  - Нормализация разделителей (пробелы, тире, точки, скобки, кавычки)
  - Двусторонний mapping original↔normalized
  - Применение масок к оригинальному тексту

### 2. PIN детектор (критично - в логах много ошибок)
- [ ] Расширить regex на 10+ вариантов
- [ ] Поддержка `PIN код`, `ПИН-код`, `пин-код(1234)`, `PIN:1234`
- [ ] Несколько PIN в одном тексте
- [ ] Контекстные слова не должны мешать

### 3. CVV/CVC как high-priority detector
- [ ] Отдельный deterministic detector
- [ ] Двусторонний context window (±20-30 символов)
- [ ] Поддержка `CVV`, `CVC`, `цвв`, `код на обороте карты`
- [ ] Значение МОЖЕТ быть ДО ключевого слова

### 4. Паспорт - расширение форматов
- [ ] Поддержка `серия 4509 номер 123456`
- [ ] Поддержка `серия 4509 / номер 123456`
- [ ] Поддержка обратного порядка `номер ... серия`
- [ ] Разумное расстояние между компонентами

### 5. Телефон с контекстом
- [ ] Контекстные ключи: `абонент`, `номер`, `моб.`, `контактный`
- [ ] Отрицательные контексты: `заказ №`, `артикул`, `ID`
- [ ] Текущая ошибка: `от абонента с номером 79031119955`

## Приоритет 2 (High - расширение типов сущностей)

### 6. Даты - поддержка вариантов
- [ ] Русские месяцы (январь, янв, Jan и т.д.)
- [ ] Формы: `15-03-90`, `15 03 1990`, `15-ЯНВАРЯ-1990`
- [ ] Контекст повышает confidence: `дата рождения` vs `встреча`

### 7. Водительское удостоверение (DRIVER)
- [ ] Ключи: `В/У`, `ВУ`, `водительское удостоверение`
- [ ] Формы: `серия 55 66 номер 778899`
- [ ] Текст между серией и номером не должен мешать

### 8. ИНН с owner classification
- [ ] 12-значный = физическое лицо рядом с `клиент`, `заемщик`, `поручитель`
- [ ] 10-значный = организация (отдельная политика)
- [ ] Контекст определяет OWNER

### 9. Место рождения и гражданство
- [ ] Должны быть отдельные от label сущности
- [ ] `Место рождения: г. Москва` → `г. Москва` (не `Место рождения: ...`)
- [ ] `Гражданство: Российская Федерация/Армения` → правильная граница

## Приоритет 3 (Medium - качество)

### 10. Span boundary validation
- [ ] Удалять role words (клиент, водитель, заемщик и т.д.)
- [ ] Для ADDRESS: стоп на `;`, `.`, новом поле
- [ ] Для ISSUER: стоп на `, повторный`, `, выданное`
- [ ] Для BIRTH_PLACE: стоп на `, оформил`, `, предъявил`

### 11. Independent entity detection
- [ ] Каждый детектор работает на полной строке
- [ ] Нахождение CARD не мешает CVV
- [ ] Несколько PIN/PHONE/INN обрабатываются независимо

### 12. Value-based linking
- [ ] Registry чувствительных значений в одном запросе
- [ ] Повторные вхождения одного значения → тот же тип
- [ ] `12.03.1985` как DATE_OF_BIRTH → везде DATE_OF_BIRTH

### 13. Final leak safety pass
- [ ] После основного NER перед возвратом
- [ ] Поиск pattern `PIN/ПИН + 4-6 цифр`
- [ ] Поиск pattern `CVV/CVC + 3-4 цифры`
- [ ] Поиск pattern `паспорт + валидная структура`
- [ ] Fail-closed: лучше пересмаскировать, чем пропустить

### 14. Conflict resolution
- [ ] Приоритет: `shape + label + semantic context`
- [ ] `9161234500` рядом с `код заказа` → не PHONE
- [ ] `321` рядом с `офис №` → не CVV
- [ ] Контекст обязателен для классификации

## Приоритет 4 (Tests)

### 15. Regression tests
- [ ] 24+ тестовых кейса из спецификации
- [ ] Проверка не только type, но и:
  - start, end
  - exact `original[start:end]`
  - отсутствие leak в masked
  - отсутствие соседнего текста в span

### 16. Dataset validation
- [ ] Применить ко всем 150k тестовым записям
- [ ] Выявить паттерны ошибок
- [ ] Итеративное улучшение
